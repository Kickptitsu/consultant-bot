# 🤖 ИИ-консультант автосервиса «Гараж 18»

Telegram-бот, который отвечает клиентам строго по базе знаний автосервиса: услуги и цены,
график, адрес, гарантия, частые вопросы. Не знает ответа — честно говорит об этом,
не выдумывает цены и передаёт вопрос живому администратору.

> Автосервис выдуманный, все данные в базе знаний — демонстрационные.

**Стек:** Python 3.13, aiogram 3, SQLite (aiosqlite), YandexGPT / GigaChat через
OpenAI-совместимый API (библиотека `openai`), pytest.

## Возможности

**Для клиента**

- **Ответы по базе знаний** — с ценами и сроками ровно как в справочнике.
- **Понимает уточнения:** помнит последние 6 сообщений за час («А для пенсионеров?»).
  Кнопка «🔄 Новый вопрос» начинает тему заново.
- **Живой оператор:** кнопка «🧑‍🔧 Позвать оператора», а если ИИ не нашёл ответа —
  вопрос уходит администратору сам. Ответ приходит в тот же чат.
- **Честность:** бот сразу предупреждает, что отвечает ИИ; согласие на обработку данных —
  до первого вопроса; `/privacy` — что хранится и удаление переписки.

**Для бизнеса**

- **Не выдумывает.** Если в ответе модели есть цена или срок, которых нет в базе, ответ
  не показывается клиенту — вопрос уходит оператору.
- **Защита от prompt injection** (попыток уговорить ИИ нарушить правила): фильтр типичных
  фраз, правила в системном промте, секретная метка против утечки промта.
- **База знаний обновляется из Telegram:** админ присылает боту файл — без перезапуска.
- **Панель `/admin`:** сколько вопросов, сколько ответил ИИ, сколько ушло оператору,
  расход токенов по дням и вопросы без ответа с подсказками, что дописать в базу.
- **Лимиты против спама и неожиданного счёта за ИИ:** длина сообщения, вопросы клиента
  в день, токены на весь бот в день; защита группы операторов от спама и блокировка клиента.
- **Три режима ИИ** (переключение в `.env`): демо-режим без ключа, YandexGPT, GigaChat.

## Как бот ищет ответ: вся база в промте, без эмбеддингов

Есть два способа дать ИИ знания о бизнесе:

1. **Вся база в промте** — с каждым вопросом модель получает весь справочник целиком.
2. **RAG с эмбеддингами** — справочник режут на кусочки, каждый превращают в набор
   чисел («координаты смысла», эмбеддинг), и перед ответом ищут несколько кусочков,
   похожих по смыслу на вопрос. Модель видит только их.

Здесь выбран первый способ. База автосервиса — несколько страниц (около 2 тыс. токенов),
а модель вмещает 32 тыс. Значит, модель видит всё сразу и не промахнётся с поиском,
не нужны векторная база и отдельный API, а новая версия файла работает мгновенно.
Цена — больше токенов на каждый вопрос; GigaChat частично снимает её кэшем: повторно
присланную базу почти не тарифицирует. Если база вырастет больше
`KNOWLEDGE_MAX_TOKENS` (`config.py`), бот откажется принимать файл и предложит
перейти на поиск по фрагментам; поиск спрятан в `services/knowledge.py`, его можно
заменить, не трогая остальной код.

## Путь вопроса

1. «Привет» и «спасибо» бот обрабатывает сам — ИИ не нужен.
2. Лимиты: слишком длинное сообщение, клиент исчерпал вопросы на день, бот исчерпал
   токены на день (тогда вопрос уходит оператору).
3. Явная попытка сломать правила — вежливый отказ без вызова ИИ.
4. ИИ получает правила, всю базу, последние сообщения и вопрос. К вопросу дописано
   короткое напоминание правил — без него небольшие модели «забывают» их к концу длинной базы.
5. Ответ проверяется: нет ли в нём кусков промта и цен, которых нет в базе.
6. «Нет ответа» или ошибка ИИ — вопрос уходит операторам.

## Запуск

1. Создайте бота в [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. Установите библиотеки (в папке проекта):

   ```bash
   py -3.13 -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```

3. Скопируйте `.env.example` в `.env`, впишите `BOT_TOKEN` и свой Telegram ID в `ADMIN_IDS`.
   Админ должен хотя бы раз нажать Start в боте — иначе бот не сможет ему написать.
4. Запустите: `python bot.py`. По умолчанию включён демо-режим — ключ ИИ не нужен:
   бот показывает подходящий раздел базы знаний.

## Подключение YandexGPT

1. Откройте [Yandex AI Studio](https://aistudio.yandex.ru/) и выберите (или создайте) каталог.
   Скопируйте **ID каталога** — он понадобится как `YANDEX_FOLDER_ID`.
2. Создайте **API-ключ** для доступа к моделям (в AI Studio — кнопка создания API-ключа,
   см. [быстрый старт](https://aistudio.yandex.ru/docs/ru/ai-studio/quickstart/)).
   Ключ показывается один раз — сразу вставьте его в `.env` как `YANDEX_API_KEY`.
3. В `.env` поставьте `AI_PROVIDER=yandex` и перезапустите бота.
4. Модель по умолчанию — `yandexgpt-5.1` (YandexGPT Pro 5.1). Другую можно указать
   в `YANDEX_MODEL`, например `aliceai-llm`.

После смены `AI_PROVIDER` бот заново спросит у клиентов согласие: тексты сообщений
теперь передаются другой компании.

## Подключение GigaChat

1. В [личном кабинете GigaChat API](https://developers.sber.ru/studio) создайте проект
   и получите **ключ авторизации** (длинная строка) → `GIGACHAT_AUTH_KEY`.
2. `GIGACHAT_SCOPE`: `GIGACHAT_API_PERS` для физлиц (есть бесплатный пакет токенов),
   `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP` для компаний.
3. `AI_PROVIDER=gigachat`, перезапуск.
   Модель по умолчанию — `GigaChat-3-Lightning`: на вопросах автосервиса она реже
   нарушала правила, чем GigaChat-2, Pro и Max, и тратила меньше токенов.
   Другую можно указать в `GIGACHAT_MODEL`.
4. Серверы GigaChat подписаны сертификатом Минцифры, которого нет в Windows и в
   стандартных сертификатах Python. Он уже лежит в проекте —
   `certs/russian_trusted_root_ca.pem` (скачан с [Госуслуг](https://www.gosuslugi.ru/crt)),
   путь к нему указан в `GIGACHAT_CA_BUNDLE`. Устанавливать его в систему не нужно:
   ему доверяет только бот. Сертификат действует до 27.02.2032.

## Передача живому оператору

Операторы — это участники обычной группы в Telegram. Отдельный список не нужен:
добавили человека в группу — он оператор.

**Настройка:**

1. Создайте группу, добавьте в неё бота и операторов. Права администратора боту не нужны.
2. Напишите в группе `/chat_id` (от имени администратора из `ADMIN_IDS`) — бот ответит ID группы.
   Если промолчал — `/chat_id@имя_бота`.
3. Впишите его в `.env` → `OPERATORS_CHAT_ID` и перезапустите бота.
4. В настройках группы включите автоудаление сообщений через месяц — там тоже
   персональные данные клиентов (см. памятку в `PRIVACY.md`).

**Как это работает:**

- Клиент нажимает «🧑‍🔧 Позвать оператора» или ИИ не находит ответа (недоступен,
  исчерпан лимит) — в группу приходит карточка: имя клиента, причина и последние сообщения.
- «✋ Взять» — диалог ваш. Если два оператора нажали одновременно, достанется первому,
  второй увидит «диалог уже ведёт …».
- Отвечайте **реплаем (Reply)** на карточку или на сообщение клиента — бот перешлёт ответ
  и поставит 👍, когда он доставлен. Ответить реплаем, не нажимая «Взять», тоже можно —
  это значит взять диалог.
- Пока запрос открыт, ИИ молчит, а сообщения клиента приходят в группу.
- «✅ Закрыть диалог» — клиенту снова отвечает ИИ. Пока запрос никто не взял,
  клиент может отменить его сам.
- «🚫 Заблокировать» (с подтверждением) — закрывает запрос, и сутки клиент не может звать
  оператора. ИИ ему отвечает как обычно, а о блокировке бот прямо не говорит —
  предлагает позвонить. Снять блокировку раньше — «🔓 Разблокировать» на той же карточке.

**Защита от спама.** Telegram пропускает в одну группу около 20 сообщений в минуту на всех
клиентов сразу — один спамер мог бы отрезать операторов от остальных. Поэтому:
не больше 5 сообщений клиента в минуту (лишние не пересылаются, клиента один раз
предупреждают), не больше 5 запросов к оператору на клиента в день (отменённые тоже
считаются), а если Telegram всё же просит подождать — бот ждёт и отправляет карточку ещё раз.

Если `OPERATORS_CHAT_ID` не задан, кнопки нет, а на вопрос без ответа бот предлагает
позвонить. Если группа стала супергруппой и сменила ID, бот напишет новый ID в журнал.

## Панель администратора

Команды видны только администраторам из `ADMIN_IDS`, в личном чате с ботом.

- **`/admin` — статистика** за сегодня, 7 или 30 дней:
  - сколько вопросов и от скольких клиентов;
  - чем закончились: ИИ ответил, нет ответа в базе, не по теме, попытки сломать правила,
    ошибки ИИ, лимиты;
  - сколько передано оператору и почему, сколько запросов ждут прямо сейчас;
  - токены: сегодня из дневного лимита и по дням.
- **«🤔 Вопросы без ответа»** — о чём чаще всего спрашивают, а в базе нет («покраска — 3»),
  и последние такие вопросы. Темы ищутся без ИИ, по совпадению слов: «покраска»,
  «покрасить» и «покраску» считаются одной темой.
- **`/kb` — база знаний:** список файлов, скачать, удалить.

## База знаний

- Файлы `.md` или `.txt` (UTF-8) в папке `knowledge/`. Заголовки `#`, `##` делят текст на разделы.
- **Обновить из Telegram:** админ присылает боту файл. Тот же файл с тем же именем
  заменяет старый, с новым именем — добавляется.
- Можно править файлы и прямо на сервере — бот заметит изменения сам.
- Услуги, которых нет, лучше перечислить прямо («Покраску не делаем») — тогда ИИ
  ответит сам, а не позовёт оператора.

## Лимиты

Настраиваются в `config.py`:

| Настройка | По умолчанию | Что будет |
|---|---|---|
| `MESSAGE_MAX_CHARS` | 1000 символов | бот просит сократить сообщение |
| `USER_DAILY_QUESTIONS` | 30 вопросов в день | клиенту предлагают позвонить или позвать оператора |
| `DAILY_TOKEN_LIMIT` | 300 000 токенов в день | до полуночи вопросы уходят операторам, админы получают предупреждение (один раз в день) |
| `OPERATOR_MESSAGES_PER_MINUTE` | 5 сообщений в минуту | лишние сообщения не пересылаются в группу операторов |
| `USER_DAILY_HANDOFFS` | 5 запросов в день | клиенту предлагают позвонить |
| `BLOCK_HOURS` | 24 часа | на сколько оператор блокирует клиента |

Один вопрос — около 2–2,5 тыс. токенов (вся база + вопрос + ответ), то есть 300 000 —
это примерно 120–150 вопросов в день.

## Персональные данные

- Перед первым вопросом бот предупреждает, что отвечает ИИ, и спрашивает согласие;
  в тексте согласия указано, какой компании передаются сообщения. Сменили провайдера
  или текст согласия — бот спросит заново.
- `/privacy` — что хранится; отзыв согласия удаляет переписку, обезличивает вопросы
  и запросы к операторам и скрывает пересланные сообщения в группе операторов.
- Переписка старше 30 дней удаляется автоматически, вопросы и запросы — обезличиваются.
- Шаблон политики и памятка для заказчика — `PRIVACY.md`.

## Структура

```
bot.py              запуск
config.py           настройки (.env) и лимиты
texts.py            все тексты для клиентов
knowledge/          база знаний (markdown)
ai/                 промт, проверки ответа, провайдеры ИИ (demo, YandexGPT, GigaChat)
services/           путь вопроса, база знаний, передача оператору, подсказки, уборка
handlers/           обработчики Telegram: клиент, операторы, админ, /privacy
database/           SQLite: переписка, вопросы, запросы к операторам, согласия
keyboards/          кнопки
tests/              автотесты
```

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

102 теста, около 6 секунд. Тесты не ходят в Telegram и к ИИ: Telegram (и группа
операторов) заменён имитацией, ИИ — демо-режимом или заглушкой, а запросы к YandexGPT
и GigaChat перехватываются и проверяются.
